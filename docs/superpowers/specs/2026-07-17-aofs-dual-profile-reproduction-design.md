# AOFS 单仓库双配置复现实验设计

日期：2026-07-17

上游仓库：`https://github.com/lalalayong/AOFS`

上游基线：`289af16d3dbbdfd1c0f98fb0dddab350be77493a`

## 1. 背景与问题

当前本地仓库来自论文作者公开的 AOFS 代码，但工作区已经包含服务器路径适配、NumPy/PyTorch/CUDA 兼容修改、少样本列表和历史训练产物。此前 NWPU-R 训练结果差，不能只归因于模型：训练只运行了约 100 epoch，论文/上游 10-shot 配置对应约 500 epoch；本地 `noval` 条件使训练期间和最终 epoch 都可能不验证；现有结果以 HBB 全类别 mAP 为主，而论文报告 novel 类 OBB mAP@0.5；少样本列表只有一个固定随机种子，且同一场景和密集图像可贡献多个实例；公开评估代码还存在数据集类别映射和缺失检测类别不计零分的问题。

因此，本项目不拆成两个仓库，而是在一个共享核心上提供两个可追踪的实验配置：`paper` 用于尽量复现论文/作者公开实现，`robust` 用于减少少样本抽样和训练过程带来的方差。

## 2. 目标与非目标

### 2.1 目标

1. 让服务器上的训练命令、数据路径、随机种子、配置文件、权重和评估结果可追溯。
2. 提供 `paper` 配置，对齐 AOFS-S 公开模型、两阶段训练、论文超参数、训练长度和三次独立运行。
3. 提供 `robust` 配置，在不替换 AOFS 核心模型的前提下加入场景感知抽样、周期性 OBB 验证和稳定的最优权重选择。
4. 统一输出 novel/base/all 三组 OBB mAP@0.5，并明确 HBB 指标只作为辅助诊断，不能与论文表格直接比较。
5. 用根目录单一台账 `MODIFICATIONS_FROM_UPSTREAM.md` 记录所有相对作者基线的源代码、配置和文档差异。

### 2.2 非目标

1. 不承诺任何单次训练必然精确达到论文数字；硬件、依赖版本、原始数据划分以及论文未公开细节都可能造成差异。
2. 不在本机执行完整 GPU 训练；本机负责代码、配置、静态检查和可运行的小型测试，完整训练在服务器执行。
3. 第一阶段不引入新的 backbone、检测头或与 AOFS 无关的算法，以免无法判断收益来自复现修复还是模型替换。
4. 不删除现有用户训练产物，不覆盖历史配置，不改写已有 Git 历史。

## 3. 总体结构

共享模型、数据加载、损失和评估代码，只把实验策略放入独立配置和启动脚本：

```text
AOFS/
├─ cfg/
│  ├─ paper/                 # 论文/公开实现对齐配置
│  └─ robust/                # 稳健训练配置
├─ scripts/
│  ├─ train_nwpu_paper.sh
│  ├─ train_nwpu_robust.sh
│  └─ eval_nwpu_obb.sh
├─ tools/                    # 少样本列表生成、数据审计、结果汇总
├─ tests/                    # 配置、抽样、评估与路径解析回归测试
├─ runs/
│  ├─ paper/                 # 服务器运行时生成，不纳入源代码
│  └─ robust/
└─ MODIFICATIONS_FROM_UPSTREAM.md
```

两种配置必须使用不同的输出目录、缓存标识和运行名称。两者可以复用同一预训练权重，但续训时必须校验 checkpoint 所属配置、shot、split 和 seed，防止串用。

## 4. 配置与路径规则

路径解析采用以下优先级：显式命令行参数 > 环境变量 `AOFS_DATA_ROOT` > 配置文件中的相对路径。源代码和受版本控制的配置不得写死 `/workspace/dataset` 或本机盘符。启动时解析为绝对路径并打印到日志；目录或标注缺失时立即失败，不允许静默回退到其他数据集。

每次运行必须保存完整的解析后参数，至少包括：profile、stage、shot、split、seed、数据根目录、类别集合、模型配置、超参数、初始权重、Git 提交和工作区是否有未提交修改。

## 5. `paper` 配置

`paper` 配置的用途是回答“作者公开代码按论文条件运行时能否接近论文表格”。它遵循以下约束：

1. 使用作者公开的 AOFS-S 模型结构、anchor、损失和两阶段流程，不加入 robust 专属算法。
2. 对齐论文给出的 SGD 参数：初始学习率 `0.001`、momentum `0.999`、weight decay `0.0005`。
3. 恢复完整训练长度。epoch 与 `max_epoch/repeat` 的转换必须在启动日志中显式展示，避免再次把 500 epoch 配成 100 epoch。
4. 每个 shot 至少运行三个独立 seed；少样本列表、运行目录和结果文件均包含 seed。
5. 保留作者公开代码的 support/meta 数据流语义，以便与公开实现可比；同时生成数据审计报告，列出每类声明 shot 数、实际读取的实例数、源图像数和场景重复度。论文文字与公开代码语义存在差异时，报告必须明确标注，不把两者混称为“严格 K-shot”。
6. checkpoint 选择只依据验证集 novel 类 OBB mAP@0.5；同时保留 `last.pt`，并记录选择 best checkpoint 的 epoch 和指标。
7. 主结果为三次运行 novel 类 OBB mAP@0.5 的均值与标准差；base/all OBB 和 HBB 指标作为辅助结果单独列出。

## 6. `robust` 配置

`robust` 先复用 `paper` 的 AOFS 核心模型和基础超参数，再只改变可明确消融的训练策略：

1. 少样本抽样优先覆盖不同源图像/场景，并限制单一图像对同一类别贡献的实例数；如果数据不足以满足约束，生成器必须报出降级原因。
2. 每个 shot 使用多个 seed，并保存每个 seed 的具体样本清单和统计摘要。
3. 固定间隔运行 OBB 验证，以 novel 类 OBB mAP@0.5 选择 best checkpoint；验证频率是显式配置项。
4. 缓存键包含数据集、split、shot、seed、profile 和标注文件摘要，避免复用旧 `.cache`。
5. 与 `paper` 的对比一次只改变一个因素，至少给出：抽样策略、checkpoint 选择、训练长度三个消融项。

## 7. 评估语义

评估入口显式接收 `--dataset nwpu`，不能依赖文件名猜测数据集。NWPU 类别顺序必须来自单一注册表，novel/base/all 分组也从同一来源生成。

OBB 主评估使用旋转多边形 IoU 和 VOC 2007 11-point AP@0.5，与论文表格口径保持一致。对于没有预测文件或没有任何预测的目标类别，AP 固定为 0，并仍计入平均值分母；不得跳过该类别缩小分母。结果文件同时写出每类 AP、novel/base/all mAP、预测数量和正样本数量。

HBB COCO 风格或其他 IoU 阈值结果必须在名称中带 `hbb`，不得只写 `mAP`。任何与论文数字的比较都必须使用 `obb_novel_map50`。

## 8. 训练与数据流程

两阶段训练分别使用独立命令和产物：

1. Base stage：在 base 类训练，输出 base checkpoint 和运行清单。
2. Few-tune stage：从指定 base checkpoint 开始，加载与 shot/split/seed 对应的 support/meta 列表，输出 `last.pt`、按 novel OBB 指标选择的 `best.pt` 和评估报告。

训练开始前执行预检：类别 ID 范围、polygon 标签列数、图像/标签配对、每类样本统计、配置与 checkpoint 的兼容性。预检失败时给出具体文件和类别，不进入 GPU 训练。

## 9. 测试与服务器验证

本机自动化测试覆盖：

1. 路径优先级和禁止硬编码路径。
2. NWPU 类别及 novel/base/all 映射。
3. 无预测类别按 AP=0 计入分母。
4. scene-aware 抽样的 shot、seed、单图上限和可复现性。
5. 训练长度换算、验证开关以及 best checkpoint 判定。
6. profile/shot/seed 不匹配的 resume 被拒绝。

服务器验证按由小到大顺序执行：数据预检、单 batch 前向/反向、短周期 smoke run、一个完整 seed、三个 seed 完整实验。只有完整 OBB 评估文件存在时才把运行标记为成功。

## 10. 变更记录规则

根目录 `MODIFICATIONS_FROM_UPSTREAM.md` 是唯一总台账。每次源代码、配置、脚本、测试或文档修改都必须在同一个补丁中更新台账，记录路径、上游行为、新行为、原因、影响的 profile 和验证方式。

台账区分三类内容：本任务开始前已经存在的本地差异、本任务引入的差异、运行生成物。自动生成二进制、缓存和训练输出不逐文件解释，但必须按目录和类型登记，且不得误称为作者源代码。

## 11. 验收标准

实现完成需同时满足：

1. `paper` 与 `robust` 可从同一仓库通过独立命令启动，路径由参数或环境变量提供。
2. 本机测试和静态预检通过，且不要求本机具有训练服务器 GPU。
3. 短周期服务器运行能生成 OBB novel/base/all 报告，并正确处理无预测类别。
4. `noval` 设置不再导致最终评估和 best checkpoint 选择失效。
5. 三个 seed 的 paper 结果可自动汇总为均值和标准差，运行清单足以复查数据与参数。
6. `MODIFICATIONS_FROM_UPSTREAM.md` 覆盖 `git diff` 中所有源代码、配置、脚本、测试和文档路径，并把历史差异与本任务差异分开。
7. 最终报告只能说明是否达到或接近论文结果，不在训练完成前作效果保证。
